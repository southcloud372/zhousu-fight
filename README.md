# 回战 · 宿傩篇

把一份《咒术回战》同人文字游戏的设定文档，做成能本地跑的网页游戏。
**引擎管数值，AI 管叙事** —— 骰子、伤害、状态全在代码里算，模型只负责写。

开局第一屏有两种引擎可选：

- **AI 接入模式**（默认）：叙事由模型实时推演，按 token 计费
- **本地模式**：36 套写死的剧情与角色预设，叙事由引擎的节拍机 + 模板完成，
  **不需要 API Key、不花一个 token**，点哪个立刻能玩。数值、战斗、时间线、
  护栏与 AI 模式共用同一套代码 —— 只是「讲故事的那张嘴」不同

> 非商业同人作品，与版权方无关联。素材说明见 [LICENSE](LICENSE)。

## 这项目有意思的地方

**别把设定直接丢给模型让它自己算。** 那样 HP 会算错、跨 20 回合会忘设定、
NPC 嘴上会冒出「弱特级」（设定里 NPC 只知道「特级」这一档）。

这里的做法是：模型每回合通过 tool call 返回一个 `proposal`，里面**只是提议**，
引擎负责校验、夹紧、然后应用。模型拿不到真值，也就改不动真值。

| 交给代码 | 交给 AI |
|---|---|
| 骰子、等级抽取、数值区间 | 术式叫什么、效果怎么描述 |
| 伤害 / 防御 / 消耗公式 | 战斗演出、分镜描写 |
| 等级压制系数 | NPC 台词 |
| 好感度、宿傩手指、态度门槛 | 行动选项 |
| 时间线推进、存档 | 身份背景、剧情钩子 |
| NPC 可见性过滤、护栏 | —— |

### 内容优先级

出现冲突时：**玩家的自定义内容 > 本契约 > 设定原文**。

玩家自己写的行动（以 **【我的行动】** 标记）、自主定义的档案、以及 rules/ 里他们自己的设定文件，
都是**指令**而不是建议 —— 冲突时以玩家为准，不要用这不符合设定敷衍过去。
（这条管的是游戏世界的规则由谁定，不涉及模型自身的行为准则。）

### 玩家的行动必须真的执行

玩家写下的行动是**指令**，不是提议。专门禁止了几种模型常见的阳奉阴违：
让攻击落空、被外部事件打断、有人及时赶到、回避结果、用台词暗示这不合设定。

**玩家可以改变任何人的命运**，包括原作主角。要杀虎杖就让他杀成，然后写代价
（其余角色的反应、关系崩塌、宿傩失去容器的后果）—— 代价是接下来会很麻烦，
不是这一刀没砍中。死亡由引擎永久登记（proposal.deaths），每回合注入状态视图，
后续很难让死者再出现。

> 引擎里**没有**「原作角色不能当敌人」这道限制了 —— 谁想打谁就打谁。
> 唯一的规矩是：原著里出现过的人，等级、生得术式、领域一律按内置原作表
> （`server/engine/canon.js`）校正，不听模型的。写"五条悟"就得是无量空处，
> 不能是个叫五条悟的二级咒灵。

**杀了关键人物，剧情会跟着改。** 虎杖、五条、理子这些人的死不只是少一个 NPC：
他撑起的那一天会被标成「已改写」（`server/engine/plotdeps.js`）。那一天**照旧会来**，
轮盘照旧为它停下，玩家照旧能介入 —— 只是内容已经不是原著里那件事了。
改写理由会写进节点表、喂给模型、显示在时间线面板上。每场战斗的结果都进
「战果」面板，同时注入模型的状态视图，约束后面的剧情。

### 四道护栏

模型迟早会犯的错，都在代码里兜住了：

1. **数值** —— 模型返回 delta，引擎夹紧（单回合掉血不超过上限 60%、好感度单回合 ±15）后应用
2. **特级细分** —— NPC 台词里出现 `弱特级/标特级/超特级/龙级` 会被自动改写成「特级」。旁白不受限，因为只有玩家看得见细分
3. **NPC 可见性** —— 喂给模型扮演 NPC 的信息只有等级和肉眼可见的伤势，没有数值
4. **原作校正** —— 原著人物当敌人时，等级/数值/术式/领域以 `canon.js` 为准，模型给的只是"谁上场"

## 跑起来

```bash
npm install
cp .env.example .env     # 然后填入你的 API Key
npm run dev
```

打开 http://localhost:5173

进游戏点「开始生成」，会真实调用 API 掷出三份属性档案（约 10 秒），之后每一步都是流式的。

### 配置

任何 **Anthropic 兼容端点**都能用，换供应商只改 `.env` 前几行：

```bash
LLM_BASE_URL=https://api.deepseek.com/anthropic
LLM_API_KEY=sk-...
LLM_MODEL=deepseek-flash
LLM_MODEL_PRO=deepseek-flash    # 开局生成这类不能错的活，可与上面不同

# 界面左上角用量表的计价（示例值，按实际账单改）
PRICE_FLASH_IN=2
PRICE_FLASH_OUT=8
PRICE_CACHE_READ=0.5
PRICE_CURRENCY=¥
```

留空 `PRICE_*` 则只显示 token 数、金额显示 `—`，不会编一个数字出来。

## 怎么玩

- **精英词缀敌人**：无名敌人 15% 概率精英化（20% 双词缀）——「狂暴」（伤害 +25%）、
  「坚壳」（受伤 -25%）、「嗜血」（按伤害三成回血）、「迅捷」（先手与脱离占优），
  名字带前缀、档案里写明规则。原著人物免疫 —— 五条悟不需要词缀
- **战利品与咒具**：胜利 25% 概率缴获一把泛用咒具（退魔短刀 / 缚骨锁 / 破魔矢……，
  原作咒具有主、不掉），仓上限 3 把；每把体术伤害 +8%、最多两把同时生效 ——
  战斗流派的第三条成长线，ups 与状态栏咒具栏都会点名
- **援护**：关系 ≥40 的本线登场角色，开打时 35% 概率赶到场内 ——
  先手必占、敌方第一手被压回去，首回合面板留名、战果记录在案。
  关系值第一次有了战斗里的兑现：想有人在背后，就先把人处好
- **成就系统**：10 项本局里程碑（初阵 / 初次杀戮 / 讨伐精英 / 百战 / 黒閃初閃・連閃 /
  改写者 / 常在场上 / 特级之路 / 終劇），全部从既有事实现算、幂等判定，达成时
  toast + 专用音；右栏成就面板亮着达成、灰着目标
- **战力预估**：遭遇询问第一行给三档判断（占优 / 胶着 / 劣势）—— 等级差与
  「几轮互换」的方向性粗估，词缀修正方向与结算一致；配合脱离成功率，
  打还是跑，决定之前先看方向
- **性能账**：存档改写紧凑 JSON（每回合落盘的 stringify 耗时与文件体积近乎减半）；
  服务端会话缓存加了 80 局的容量上限（长挂内存不再只增不减，淘汰的安全网是磁盘存档）；
  前端日志条目 React.memo 化 —— 长局每来一条新正文只渲染新增的那条，几百条旧账不再陪跑；
  回合的模型状态视图一次计算两处复用
- **乘胜追击**：连胜每场 +5% 战利品掉率（封顶 +15%，败/平清零），同名咒具不再重复掉
  —— 掉率让给池子里没见过的东西
- **AI 也读得到你的战果细节**：缴获的咒具、援护你的角色都会写进战斗摘要与
  skip/剧情模式的演出简报 —— 主循环的模型下一轮叙事时知道「你兜里多了把退魔短刀、
  是谁替你挡了那一手」，而不是只看到一堆数字
- **敌方溃逃**：狡诈与死守的敌人血线 ≤15% 时会跑（35% 每回合尝试）——
  战斗多了一种结局：**击退**。玩家胜但没有尸体：无缴获、无处置、跨级跃升不触发；
  介入战当场按「卷入」记进时间线。狂攻型不逃 —— 那类东西分不清撤退和死亡。
  想要战利品和处置权，就得在它逃掉之前终结它
- **资源循环补全**：静养一天现在也回咒力（+40% 上限）——血靠治、咒力靠歇；
  家入硝子把你整个人缝好，血与咒力一起满。咒力不再是只能靠战斗中防御回气的独苗
- **关系里程碑**：某段关系跨过 ±60 / ±80 的那一刻，引擎点名一行
  （「可以托付后背了」「结成了死仇」）—— 数字变坎，坎变成玩家看得见的岔路。
  配套成就「挚友」「宿敌」；挚友还会加深援护（触发概率 +0.15）——
  关系投资的每一档都有实际回报
- **改写日的叙事正确性**：被改写的原作节点（撑起它的人没了）轮到那一天时，
  本地模式不再照原著念剧本，改念改写理由 —— 「那一天早已被改写」
- **NPC 生态（本地模式）**：熟人事件按关系加权（越熟越容易遇上），
  引擎记着遇过几次 —— 初见是搭话、再见是默契、三次以上是不用寒暄的老友。
  关系网有了时间维度
- **词缀池扩到六条**：新增「再生」（每回合结束回 2% 血——磨血流的天敌）与
  「御咒」（受到的术式伤害 -25%，体术照旧）；**精英击杀掉率翻倍**（行走的宝箱，
  硬仗的回报配得上风险）；战利品带来源注记（「缴获自狂暴·食骸咒胎」）
- **自动存档槽**：战斗结算与终章自动落一个节点级快照（「自动 · 铁蔷薇 · 第2回合」），
  同会话覆盖写。死了之后两级后悔药：检查点回到上一场开打前，自动档回到上一个里程碑
- **连胜展示**：本局战绩多一行「连胜 N 场（掉率加成中）」—— 乘胜追击看得见
- **完胜**：零承伤取胜会标记进战果（战果面板「· 完胜」），并解锁成就
  「完胜」—— 打得漂亮本身就是奖励
- **AI 的时间感**：模型状态视图注入「下一原作节点」（日期 / 节点名 / 剩余天数 /
  危险度，全模式）—— 剧情向的叙事不再可能随手把日期推过头
- **体验打磨**：自定义行动预填上一次的输入（常用动作不用重打）；咒具标签带
  来源注记（「缴获自…」）；战果面板的「击退」有专属配色；存档删除改两段确认
  （误触不丢档）；客户端日志超 320 条自动折叠最老一段（DOM 不随回合无限膨胀）
- **数值量级校准**：一级几千 → 弱特几万 → 标特十几万 → 超特几十万 → 龙级百万级
  （区间首尾相接，反向查表无间隙）。38 套本地预设与 AI 掷骰共用这张表
- **无下限屏障**（原著机制）：五条悟的术式与体术都打不穿——「触碰不到他」，
  只有**领域必中**（或魔虚罗那样的适应）能造成伤害。档案、战力预估、遭遇询问
  三处都会提示这一规则；领域展开的必中重击与追斩可以穿透
- **开局五档属性**：AI 开局掷**五份**属性档案，档位固定覆盖 二级 / 一级 /
  弱特 / 标特 / 超特——强度是玩家的选择，不是抽签；本地模式每条线的预设
  也全覆盖这五档（各线都有超特剧本：断罪 / 灵视 / 终章执笔人）
- **血条归零 = 死亡 = 终局**：不再是「濒死靠治疗」的叙事状态 —— 战斗败北、
  同归于尽、剧情里的透支与重伤，只要血条到 0 就当场死亡。死亡层列出死因、
  日期与本局战绩，出路三条：**从上一场开打前重来**（战前检查点，每场战斗
  自动落一份，恢复后遭遇重新问你要不要打）、读手动存档、或认下这一局。
  服务端闸门同步拦截一切推进性操作（409）—— 刷新、换设备都赖不掉
- **演出卡顿已修**：过场根层首帧即独立合成层（translateZ + contain:paint），
  大字辉光模糊半径减半，集中线 will-change 一次栅格化 —— 特写挂载不再挤压主树
- **演出层的视觉语言：漫画分镜** —— 大字过场由四层构成：
  **集中线**（repeating-conic-gradient 一次成像、radial-mask 只在边缘显形，进场后归静帧）、
  **术式阵**（两道反向缓转的虚线环，只陪领域三型登场；transform-only，不逐帧布局）、
  **斩线**（黒闪专用的一道斜 14° 横贯亮线 + 细回声）、**遮幅**（上下发丝线收成宽银幕）。
  光晕一律椭圆微偏，色随类型；命中冲击从圆斑改成**椭圆细环**（环心即命中点，暴击更红、
  必中偏紫、挨打血色）。`prefers-reduced-motion` 下全部装饰层让路
- **终局与谢幕**：排期全部走完后，顶栏出现「终章」按钮（服务端按 `endingReady` 判定）——
  谢幕文案从这一局真实打出来的战绩里长出来（改写了哪些天、倒下了谁、几颗黒闪），
  没做过的事不硬编（没有改写就写"你没有改写任何一天"）。谢幕是句点不是锁：
  overlay 关掉后世界照常可玩；再点「终章」看到的是同一份（幂等）。AI 模式在排期
  走完后的每个回合都会收到「终局」提示——把故事推向收束，而不是默认无限日常
- **节点大字过场**：原作节点当天（剧情向的剧情回合、以及一切介入战），一屏节点名大字
  过场——和领域展开同级的排面，冷紫墨色、带着「那一天」的场景描述
- **脱离成功率摆上按钮**：遭遇战询问里的「尝试脱离」会写明成功率（按速度比实算，
  同战斗内的口径）。跑不跑得掉，玩家在决定之前就该有数
- **手动战斗可「自动出招」**：行动栏上方的开关，按「领域 → 术式 → 防御回气 → 体术」
  自动递招（不替你用反转术式——那是不占回合的手感判断）。一场几十回合的仗不用每回合点，
  随时关掉插一手；战斗结束自动复位。回合上限 30，第 26 回合起界面预警「判定将至」
- **本局战绩**：右侧状态栏的一张总账卡——回合数、交战、击杀、介入过的正日子、
  黒闪颗数、改写的节点。全部由引擎从既有事实现算，不另记账本
- **成本与体积（商用加固）**：每回合的 system 里「设定原文 + 契约」稳定段自动打
  提示词缓存断点（供应商按缓存命中计费，通常约一折；不认 cache_control 的端点
  自动降级，`LLM_PROMPT_CACHE=0` 可关）；界面日志封顶 200 条，长局存档不再随回合线性膨胀
- **合成音效（零素材，WebAudio 现场生成）**：命中、暴击、黒闪、领域展开、胜负、升级、顿悟
  各有分档的 cue —— 音色全部由振荡器 + 包络合成，没有音频文件、没有版权问题。
  音量的审美红线写在测试里（刺耳波形不进高频段、单事件不超满幅、总闸 0.16）；
  默认开启，顶栏「音效」一键关、记住选择。黒闪的听觉节奏是「一闪 → 顿 → 轰」，
  和它"时间停了一拍"的视觉特写同一套语言
- **可见的积累**：状态栏有「黒闪累计」读数（攒得越多越容易再闪，承诺看得见）；
  连击 3 层与满层会点名提示；伤害飘字按占血条比例分档放大，黒闪有专属配色
- **本地模式的界面诚实度**：本地局左上角显示「本地模式 · 零 token」徽标，
  而不是一块永远为 0 的用量表
- **黑闪（原著机制，两模式共享）**：体术连击到第三拳起，暴击的"深处"有概率升格为
  **黑闪** —— 咒力在命中的亿万分之一秒内与打击完全同步，伤害按几何级炸开（×2.6），
  附带全屏「黒閃」特写与打断。打出过的身体会记住那种感觉（原著设定）：
  累计颗数越多越容易再闪，封顶为暴击率的一半。术式不闪 —— 黑闪是带咒力的拳头
- **原作沉浸**：原作人物都配了**声线卡**（说话风格 + 招牌台词，AI 模式拼进提示词、
  本地模式在切磋与节点战里开口）；24 个原作节点各配了**「那一天」的场景描述** ——
  节点当天，AI 的提示词与本地模式的正文都会还原原著场面（帷幕、广播、该出现的人），
  而不是只报四个字的节点名
- **轮盘顿悟日**：战斗向每天 6% 概率触发「顿悟——身体先于意识明白了」，
  当天修炼收获翻倍（不翻倍受伤风险、不额外耗时间）。独立随机源，手感回归不受扰动
- **本地模式（无需 API）**：主页点「本地模式 · 预设剧情」→ 36 套预设按故事线筛选，
  每套 = 一段四拍剧情 + 一份设计好的角色（等级、数值、术式、领域、身份、穿越落点全部印在卡上）
  - 数值分布刻意对齐 AI 模式开局的权重结构（一级约占一半、特级稀有），六种「倾向」
    （均衡/脆杀/重装/蛮打/术主/疾袭）决定数值在区间内的取点 —— 等级永远由数字反推，和 token 模式同一条铁律
  - 剧情走完四拍后自动衔接**程序化续写**：按本线原作节点排期一天天推进
    （侦查 / 切磋 / 静待），到节点当天选择介入那场仗或避开 —— 打完由引擎把那一天记进时间线
  - 自由行动走意图识别（攻击/对话/撤离/查勘），连续两次后故事自动翻页；
    所有数值变动仍以「提议」身份过 clampProposal，本地模式没有权限绕过护栏
  - 战斗演出、回合演出、修炼文案由引擎模板生成 —— 面板里的事实（谁出招、暴击、被打断）都在，只是不押韵
- **两种游玩模式**：开局第一屏选，和故事线是两个独立的轴
  - **剧情向**（默认）：战斗占 70%+，穿插人物关系与任务推进，节奏有起伏
  - **战斗向**：空闲时间泡在修炼里，剧情当天直接打进战场
  - 模式只改叙事配比，**不碰任何数值**（等级压制、伤害公式照旧）
  - 开局后点顶栏那个模式徽章可以随时切换
- **三条故事线**：开局第一屏选线，各线的时间、人物、原作节点完全不同
  - **宿傩篇**（2018）：虎杖吞下宿傩手指之后，10 个原作节点
  - **怀玉篇**（2006）：五条悟与夏油杰的高专时代，8 个原作节点，阵容是天内理子 / 伏黑甚尔那批人
  - **未来篇**（2029）：**原作完结之后的原创延伸**，节点与穿越时间点没有原作依据，按世界观推演
- **开局四步**：故事线 → 属性 → 身份 → **穿越时间**，后三步都支持「三选一 + 自主定义」
- **跨篇衔接**：篇章之间的时间空白不跳过，拆成三段历练由玩家决定怎么用。
  怀玉篇 → 宿傩篇跨 11 年，宿傩篇 → 未来篇跨 10 年。每段选一个方向
  （苦修 / 冥想 / 术式钻研 / 游历），引擎按方向结算成长。
  换篇时保留姓名、术式、领域、天赋，原作节点表换成新篇的，
  **两篇都登场的人会记得你**（比如五条悟）。三段积累够就直接提升一个等级，没有突破门槛
- **穿越时间决定起局**：三选一里**保底有一份是最开篇**（2018年6月·宿傩手指）。
  选了它一切都还没发生；选涩谷事变则五条悟已被封印、涩谷封场，
  七个原作节点成了不可更改的既定事实。起始日期、时间线进度、开局处境都由它决定
- **自主定义穿越时机**：写「我想穿到涩谷事变前一个月」即可。日期是自定义的，
  但**原作进度与危险度继承自最接近的既有节点** —— 否则哪些事件已经发生无从算起。
  界面会标明锚定在哪
- **开局四选一**（属性 / 身份各）：引擎掷三份属性档案，外加一项**自主定义** —— 写一段你想要的打法，
  引擎重掷数值、模型按你的描述生成术式与领域。身份同理（类型由模型按描述判定，关系值随即重掷）
  - ⚠️ 等级仍由引擎按设定概率掷出，**不能指定** —— 那套分布是战斗平衡的地基
- **每回合** 从选项里挑，或者**直接在「自定义行动」里写你想做的事**
- **选项上方有一行局面提要**：一句话说清「你在哪、发生了什么、手上有什么」，
  不用往回翻就能决定选什么。正文与台词保持原样，提要是额外加的一行
- **遭遇战** 先问要不要打（可以尝试脱离，按速度判定成功率），选了迎战再选战斗模式
- **战斗三模式**：手动回合制 / 快速结算 / 剧情演出。跳过与剧情的胜负也由引擎算，模型只写过程
- **反转术式（不占回合）**：手动战斗的行动栏上方单列一行。按一下当场回血、**回合数不动**，
  敌方也不出手，之后照常挑一个行动。每回合限一次，咒力不够 / 血满 / 用过了都会写在按钮上
  （它不是"多用一次技能"，是"这一手的附带动作"）。没练成的角色这一格**照样在**，
  只是灰着并写明去哪儿练 —— 技能栏空着的话，玩家不会知道有这么一个技能
- **血条当场就动**：反转术式走的是独立接口，不推进回合，但每次都返回角色快照，
  所以右侧状态栏和按钮态是同步刷新的，不会出现"点了技能血条不动、以为没生效"
- **受伤时多出「疗伤」入口**（血条低于六成或状态不正常才出现），三条路子明码标价：
  - **反转术式自愈** —— 烧咒力，**不占时间**，会这招的人当场解决
  - **静养一天** —— 回 18%，花掉一天
  - **去高专找家入硝子** —— 直接治满，花一天 + 欠两分人情（关系太差就吃闭门羹）
  - 战斗中的反转术式和平时自愈共用同一张档位表（`formula.js`），只有回血量按
    「战斗外能静下心来做」放大 1.5 倍，咒力消耗不变 —— 同一招不会两处不一样
- **战斗向的日常轮盘**（只在战斗向出现，在正文和选项之间）：
  - 两段剧情之间的空闲时间，**一天转一次**，落在六个方向之一就涨一点属性
    （体能训练 / 咒力冥想 / 术式演练 / 体术实战 / 反转术式修习 / 领域雏形冥想）
  - 方向是**随机**的，天赋会把轮盘往对应方向拽；连练会疲劳，收益递减到 0.45 倍触底
  - **停站是「每个小剧情节点」，不是章节**：三条线各自的节点排期（`storylines.js` 的
    `nodeSchedule`）就是停站表 —— 宿傩篇 10 站，怀玉篇 8 站，未来篇 6 站。
    虎杖吞手指、死刑缓期、高专入学这些同样算一站
  - 同一天连着两个节点的（少年院任务 & 宿傩夺舍都是 2018-06-24；怀玉篇的
    甚尔之战 & 五条觉醒同为 06-08-20）会**连着打两场**，打完第一场轮盘立刻指着第二场
  - **属性是攒满 100% 才跳一次**（血条上限 / 咒力上限 / 伤害 +10%，咒力效率 +5%），
    一天只推几个点。所以右边状态栏多了一整块**「成长」面板**：六条进度条给出
    "这个方向练到哪儿了"，转完一天的日志也会写 `进度 +6.2% → 44%`。
    不摆进度的话，玩家转完一天回头看右边，数字纹丝不动，只会以为轮盘白转了
  - 「练到剧情当天（N 天）」一口气推完，只回一张合并日报（各方向天数 + 六条进度），
    不是十九行流水账
  - **推到剧情节点当天，这一站就锁住了**：`/wheel/spin` 被拒（再转一天，这一天就过去了，
    节点会被记成「错过」），轮盘让位给这一场仗的「要不要打」询问 ——
    可以迎战，也可以脱离；脱离等于这一天你没在场，该发生的照样发生。
    引擎自己也守这条线：`spinWheel` 撞上节点当天返回 `kind:'blocked'`，不靠调用方自觉
  - 排期走完（最后一个节点打完）就不许再空转了，闸门直接指向顶栏的「跨篇」
  - 重伤 / 濒死那一天只能躺着回血，硬练会把命练没
- **跳过当天修炼**（只在剧情向出现）：六个项目，有天赋加成与递减效应，连续跳过 3 天后失效一次。
  战斗向用轮盘取代了它 —— 留着"指定方向练一天"，轮盘就没人转了
- **随时存档**，刷新页面自动接回进度

## 实现上几个绕不开的坑

**这个端点默认开思考模式，而思考模式和强制 `tool_choice` 互斥。**
结构化调用必须带 `thinking:{type:"disabled"}`，否则报
`Thinking mode does not support this tool_choice`。

**流式 + 结构化是可以兼得的。** `llm.js` 的 `extractPartialString()`
在 tool 入参的 JSON 还没生成完时就把 `narration` 字段抠出来推给前端，
所以既有打字机又有结构化输出。代价是 schema 里 `narration` 必须排第一位。
它的正确性用一条性质定义：**任意位置截断缓冲区，返回的都必须是完整解析结果的前缀**。

**喂给模型的不能是整个 state。** `modelStateView()` 把完整状态（含全部历史正文）
从 57617 字符压到 624 字符（92x）。少了这一步，每回合都在重复计费所有历史。

**长线记忆**：历史超过 24 条时后台压成编年史，只保留最近若干轮原文。

## 设定原文里的坑（已在代码里处理）

| 原文 | 问题 | 处理 |
|---|---|---|
| 初始概率九项 | 相加是 **101%** | 按原文「按比例归一化」，实测分布 1/10/15/50/10/10/5 |
| 第 82 行 vs 第 117 行 | 伤害公式两处不一致 | 统一采用面板版，留了开关可回退 |
| 特级内部三对压制 | 在九级表里下标差**都是 1**，按等级差查表会让「超特 vs 龙级」错用「弱特 vs 标特」的系数 | 改为按「较低一方的细分档位」索引，跨档逐级复合 |
| 防御公式 | `咒力效率 × 20` 是**固定加法**，而体术伤害横跨五个数量级 → 低级时吞掉全部攻击力 | 见下 |

### 平衡修正：防御公式

原文 `防御力 = 体术伤害 × 0.3 + 咒力效率 × 20`。照字面实现会出事：

```
等级   体术伤害  防御力   体术净伤  术式净伤  血条    体术致死  术式致死
四级           8       12     1（地板） 1（地板）   75      ∞        ∞
三级          15       17     1（地板）       5   150      ∞     30 击
二级          30       23          7        40   300   43 击     8 击   ← 超过 30 回合上限
一级         115       53         63       454  1150   19 击     3 击   ← 只有这里正常
```

**四级同级互殴双方恒打 1 点、需要 75 回合，而引擎回合上限是 30 —— 必然强制平局。**
这是真跑起来才发现的，断言全绿但打不动。

改成量级相对式 `体术伤害 × (0.3 + 效率 × 0.2)`，`0.2` 照原式在**一级**的配比校准，
锚点手感几乎没动。另加伤害地板（至少为原始伤害的 10%），从根上杜绝「防御 ≥ 攻击」。
系数都在 `formula.js` 顶部。

## 设定文件

模型要遵守的世界观与叙事规范放在 `rules/` 下，按以下顺序取用：

1. **你自己的设定** —— `rules/` 下任意 `.txt` / `.md`（多个时取文件名靠前的）
2. **`rules/default-rules.md`** —— 仓库自带的精简版，保证 clone 下来就能跑

仓库里已经带了 `rules/模拟回战-宿傩.txt`，所以开箱即用。

**数值表、伤害公式、等级压制系数、领域规则全部由引擎代码强制执行**，
写在设定文件里也不会生效 —— 那份文档只负责模型该知道的世界观、叙事风格与角色约束。
所以换设定比想象中简单：只要覆盖世界观、叙事规范、角色红线、敌人与选项设计这几块。

> ⚠️ 若你放进 `rules/` 的是**第三方撰写的文本**，它不在本项目的 MIT 许可范围内，
> 请同步更新 [LICENSE](LICENSE) 的第三方内容声明。

## 已知不足

- 领域的「必中效果」是模型写的散文，引擎只做了通用加成（+50% 输出、防御减半）。
  想要每个领域都有独特机制，需要给领域加结构化字段
- 相性表恒为 1，地形没有建模
- 濒死是**叙事状态**而非死亡判定：引擎会把「血条归零、不治疗就死」写进战报交给模型，
  但玩家会不会真死由模型叙事决定，没有强制的死亡/复活流程
- 战斗结算后会自动推一个回合让剧情接上，这一回合不接受输入
- **日常轮盘的数值是靠跑批调出来的，不是推导出来的**：`wheel.js` 顶部那个 `DAY_SCALE = 1.6`
  对应「19 天空档 ≈ 2~3 次数值跳变」，是按当前等级区间实测的。改 `tables.js` 的数值表
  或修炼区间之后，这个手感会跟着变，需要重跑 `wheel.test.mjs` 里那条 18 天空档的回归
- **节点之间的天数差是原作日期，没有按"一天一转"的体感重新标定过**：最长的空档
  （涩谷事变 → 死灭回游）有 20 天，最短的只有 0 天（同一天两个节点）。所以「练到剧情当天」
  的按钮时长差别很大，有的空档还没练热就到站了 —— 想要一天一天走完就得点很多次「转一天」
- 轮盘界面只在 jsdom 里渲染验证过（角度、扇区、进度条、按钮态），**没有在真实浏览器里肉眼看过**；
  指针动画是 CSS transform 过渡，真机上是否顺眼未验证
- 只在 Node 20+ 与 Chromium/Firefox 上验证过
